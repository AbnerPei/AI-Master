# `视频号` 人物蒸馏工作流

这份手册记录如何把一条 `视频号` 链接沉淀成“人物主档 + 来源证据 + 人物蒸馏”三层结构，并为后续继续补 `公众号`、`书籍` 等资料留好入口。

## 一、目标结构

输入不是“一个平台账号”，而是“一个人”。

一次接入后，知识库会形成三层：

- 人物主档：现有 `raw/A_AI-Gurus(AI大神)/AI 大神 - {姓名}.md` 或 `raw/A_AI-Content-Creator(AI 创作者)/AI 创作者 - {姓名}.md`
- 来源索引：`raw/.../{人物卡片同名目录}/来源索引.md`
- 人物蒸馏：`raw/.../{人物卡片同名目录}/人物蒸馏.md`

同时会保存：

- `档案.json`
- `证据/{平台}-{来源ID}.json`
- `媒体/` 下的封面或本地视频副本

## 二、脚本入口

仓库内脚本：

```bash
python3 scripts/fetch_wechat_channels_source.py "<视频号URL>" --download-cover
python3 scripts/enumerate_wechat_channels_creator_catalog.py "<视频号URL>"
python3 scripts/creator_dossier.py ...
python3 scripts/build_creator_skill.py --dossier-dir "..."
```

职责拆分：

- `fetch_wechat_channels_source.py`
  - 拉取单条 `视频号` 来源
  - 保存 `meta.json`、`raw.json`、封面和剪藏 `Markdown`
- `enumerate_wechat_channels_creator_catalog.py`
  - 从单条 `视频号` seed 生成“创作者内容枚举清单”
  - 显式记录当前是公开全量枚举、部分枚举，还是需要 `Mac WeChat` 自动化兜底
  - 为后续批量下载阶段生成统一条目与队列状态
- `creator_dossier.py`
  - 把来源接入到同一个人物档案
  - 生成来源索引、人物蒸馏和证据 `JSON`
- `build_creator_skill.py`
  - 从人物档案编译出仓库内可复用的 `skill` 资产
  - 生成 `SKILL.md`、参考资料索引和 `manifest`

其中 `creator_dossier.py` 设计为“单来源接入器”：

- 每次接入一条来源
- 自动归并到同一个人物档案
- 已存在的来源不会重复造册，只会更新

## 三、`视频号` 最小命令

如果手里只有一个 `视频号` 短链，推荐先抓剪藏：

```bash
python3 scripts/fetch_wechat_channels_source.py \
  "https://weixin.qq.com/sph/AeRWpe7T0D" \
  --download-cover
```

如果目标是先判断“能不能从这条 seed 反推出这个创作者的更多内容”，先跑枚举器：

```bash
python3 scripts/enumerate_wechat_channels_creator_catalog.py \
  "https://weixin.qq.com/sph/AeRWpe7T0D"
```

它会输出两类结果：

- `Clippings/视频号/{finder_id}_catalog.json`
- `Clippings/视频号/{创作者名}_内容枚举.md`

注意：

- 当前公开路径很可能只能确认到 `seed` 这一条视频
- 如果脚本把状态写成 `partial`，意思是“当前只拿到部分，不代表创作者只有这些内容”
- 此时应该进入 `Mac WeChat` 主页级自动化，而不是人工逐条点开视频页面

然后再把生成的 `Clippings/视频号/` 文件接入人物档案。

如果当前已经有 `Clippings/视频号/` 里的剪藏，可以直接这样接入：

```bash
python3 scripts/creator_dossier.py \
  --creator-name "李尚龙" \
  --category "AI 大神" \
  --stars 5 \
  --platform "视频号" \
  --source-type video \
  --seed-url "https://channels.weixin.qq.com/finder-preview/pages/sph?id=AU25W7Em6f" \
  --source-id "AU25W7Em6f" \
  --title "你以为的“贩卖焦虑”只是你没见过的“世界常识”贩卖焦虑" \
  --source-json "Clippings/视频号/AU25W7Em6f_meta.json" \
  --clipping-markdown "Clippings/视频号/你以为的“贩卖焦虑”只是你没见过的“世界常识”贩卖焦虑.md" \
  --cover-path "Clippings/视频号/AU25W7Em6f_cover.jpg" \
  --published-precision unknown \
  --published-source "existing-clipping-meta" \
  --download-status missing \
  --download-note "当前仅有剪藏和封面，未包含本地视频文件。"
```

## 四、发布时间字段

视频类来源必须显式带这些字段：

- `published_at`
  适用于拿到精确时间戳，例如 `2026-06-12T10:30:00+08:00`
- `published_date`
  适用于只有日期，没有具体时分秒
- `published_precision`
  只能是 `exact`、`date-only`、`estimated`、`unknown`
- `published_source`
  说明时间来自哪里，例如 `api-field`、`page-text`、`manual-input`

原则：

- 不知道就写 `unknown`
- 绝不能把模糊时间伪装成精确时间

## 五、本地视频副本

如果已经通过其他方式把视频下载到本地，例如先用：

- [[OpenSpec 安装与使用]]
- 或参考原始教程：[如何下载视频号的视频](../../raw/C_Courses(课程)/T_Tutorials(教程)/如何下载视频号的视频/如何下载视频号的视频.md)

拿到本地视频文件后，再把路径交给脚本：

```bash
python3 scripts/creator_dossier.py \
  ... \
  --local-video "/absolute/path/to/video.mp4" \
  --download-status saved \
  --published-at "2026-06-12T10:30:00+08:00" \
  --published-precision exact \
  --published-source "manual-confirmed"
```

脚本会把本地视频副本复制到该人物档案目录下的 `媒体/`。

如果当前拿不到本地视频，也要显式记录：

- `download-status=missing` 或 `failed`
- `download-note=为什么没有`

## 六、后续补 `公众号` / `书籍`

脚本本身已经支持统一来源结构，后续只需要继续沿用：

- `--platform`
- `--source-type`
- `--source-id`
- `--title`
- `--description`
- `--published-at` / `--published-date`

关键不是平台，而是确保：

- 归并到同一个 `creator-name`
- 每条来源都有清晰证据
- 蒸馏结果能回指到具体来源和时间

## 七、编译成个人理解 `skill`

当某个人物已经有：

- `档案.json`
- `来源索引.md`
- `人物蒸馏.md`
- 至少一条可回链证据

就可以继续编译：

```bash
python3 scripts/build_creator_skill.py \
  --dossier-dir "raw/A_AI-Content-Creator(AI 创作者)/AI 创作者 - 姜胡说"
```

默认输出到：

- `raw/A_Tools(工具)/skills/generated/{人物名}/SKILL.md`
- `raw/A_Tools(工具)/skills/generated/{人物名}/参考资料索引.md`
- `raw/A_Tools(工具)/skills/generated/{人物名}/skill-manifest.json`

注意这一步的原则：

- `SKILL.md` 只写触发条件、能力边界、当前人物理解和使用原则
- 原始证据仍留在人物档案目录，不直接塞进 `skill` 指令正文
- `skill` 必须回链到人物档案、来源索引和证据 `JSON`

## 八、创作者全量枚举的现实边界

当前阶段要把这件事拆成三层来理解：

- 公开 `seed` 解析：通常能拿到单条 feed 元数据、作者可见名称和发布时间
- 公开创作者全量枚举：当前不稳定，很多时候拿不到稳定的创作者主键或列表接口
- 客户端兜底：如果目标是尽量接近“全量”，要转向 `Mac WeChat` 主页级自动化

所以正确做法不是“要么一口气全拿到，要么不做”，而是：

- 先把已确认的条目和发布时间落盘
- 显式记录本次只是 `partial`
- 把失败原因和下一步自动化路径一并写出来
