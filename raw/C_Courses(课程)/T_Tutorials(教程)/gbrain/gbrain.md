# `gbrain`

## 项目概览

| 项目 | 说明 |
|------|------|
| 仓库 | https://github.com/garrytan/gbrain |
| 作者 | `Garry Tan` |
| 定位 | 面向 `AI Agent` 的“长期记忆 / 公司知识大脑 / 检索与综合层” |
| 技术栈 | `TypeScript` + `Bun` + `Postgres` / `PGLite` + `MCP` |
| License | `MIT` |
| GitHub Star | `22516`（整理时） |
| 默认分支 | `master` |

`gbrain` 不是普通的笔记应用，也不只是一个 `RAG` 检索库。它更像是给 `AI Agent` 准备的一层“可查询、可综合、可持续更新”的知识大脑。

作者在 `README` 里把它描述成：

- 不只是返回相关页面，而是直接生成带引用的答案
- 不只是向量检索，还会自动构建知识图谱
- 不只是个人知识库，也支持团队级、权限隔离的“公司大脑”
- 不只是一次性导入，还支持持续摄入、夜间整理、自动修复引用与去重

如果用一句中文来概括：

> `gbrain` 想解决的是：让你的 `Agent` 不再“只会查代码上下文”，而是拥有长期记忆、结构化关系和跨资料综合能力。

## 这个项目解决什么问题

很多知识库工具只能做到“搜到内容”，但真正使用时，你仍然要自己打开 5 篇笔记、10 个片段，再手动总结。

`gbrain` 的目标是把这个过程前移：

- 先做混合检索：向量、关键词、重排、图谱信号一起参与
- 再做综合回答：把多份资料整理成最终答案
- 同时给出引用来源
- 还会指出“目前知识库还不知道什么”

也就是说，它强调的不是“找得到”，而是“答得出来，并且知道哪里还缺信息”。

这点很适合下面几类场景：

- 个人长期知识库
- 创业团队内部知识库
- `Claude Code` / `Codex` / `Cursor` 这类编码代理的长期记忆层
- 会议、邮件、语音、笔记、项目资料的统一归档与检索

## 核心能力

### 1. 检索 + 综合回答

项目区分了两种查询方式：

- `gbrain search`：返回原始检索结果，适合自己翻看材料
- `gbrain think`：返回综合后的答案，附带引用与“信息缺口”提示

这说明它不想只做一个“更高级的搜索框”，而是想做一个真正的“脑层”。

### 2. 自动知识图谱

`gbrain` 会在写入页面时自动提取实体引用，并建立类型化关系，例如：

- `works_at`
- `invested_in`
- `founded`
- `attended`
- `advises`

这意味着它不仅能按语义相似度找内容，也能按“人物 - 公司 - 事件 - 关系”做图谱遍历。对于“谁和谁有关”“这个人最近参与了什么”“某家公司有哪些上下文”这类问题，会比单纯向量检索更强。

### 3. 面向 `Agent` 的安装与使用方式

`README` 里反复强调，`gbrain` 最适合由 `AI Agent` 来安装和操作。

它提供了给代理直接执行的安装协议：

```text
Retrieve and follow the instructions at:
https://raw.githubusercontent.com/garrytan/gbrain/master/INSTALL_FOR_AGENTS.md
```

这很有意思，因为它不是把“用户手工点点点安装”作为第一入口，而是直接把自己设计成：

- 能被代理部署
- 能被代理调用
- 能通过 `MCP` 接到其他代理工具链里

### 4. `MCP` 集成能力

它支持把自己的能力暴露为 `MCP` 服务，可接入：

- `Claude Code`
- `Codex`
- `Cursor`
- `Windsurf`
- `ChatGPT`
- `Perplexity`

如果你平时就在用编码代理，那么 `gbrain` 的一个非常实际的用途，就是给这些代理补上一层“跨会话长期记忆”。

### 5. 多种数据摄入方式

从 `README` 看，它支持的数据输入方式很多：

- 直接 `capture` 文本
- 从文件导入
- 从标准输入导入
- 通过 `Webhook` 接收内容
- 从本地收件箱目录同步
- 扩展第三方 `skillpack` 做自定义摄入

它想做的是统一入口，把碎片化信息持续灌进“脑”里，而不是只在查询时临时拼接上下文。

### 6. 支持“公司大脑”

这是 `gbrain` 和很多个人知识库项目很不一样的一点。

它不仅面向个人，还强调团队隔离和权限控制：

- 每个成员只看到自己有权限看的内容
- 可作为团队共享的机构记忆层
- 支持 `OAuth`、`scope`、`HTTP MCP`

如果你的目标是“团队知识中台”而不是“个人笔记工具”，那这个方向会更值得关注。

## 快速理解它的架构

可以把 `gbrain` 粗略理解为下面这层结构：

```text
输入层
  ├─ 笔记
  ├─ 会议
  ├─ 邮件
  ├─ 语音
  └─ Webhook / Agent 写入

存储层
  ├─ Markdown 脑仓库
  └─ Postgres / PGLite 检索索引

能力层
  ├─ Hybrid Search
  ├─ Knowledge Graph
  ├─ Synthesis / Think
  ├─ Jobs / Dream Cycle
  └─ Schema Packs

接入层
  ├─ CLI
  ├─ MCP
  └─ AI Agent
```

这里最关键的不是某一个点，而是它把这些能力打包成了一个完整闭环：

`输入 -> 索引 -> 图谱 -> 综合 -> 代理调用 -> 持续更新`

## 安装方式（基于仓库文档的整理）

`README` 里给了几条主路径：

### 1. 给 `Agent` 自动安装（最推荐）

适合已经在使用 `OpenClaw`、`Hermes` 或其他能执行命令的代理平台的人。

核心思路是：

- 把 `INSTALL_FOR_AGENTS.md` 交给代理
- 由代理完成环境准备、初始化、技能装载和验证

### 2. 给编码代理添加记忆层

如果你已经在用 `Claude Code` 或 `Codex`，它推荐的入口是：

```bash
gbrain init --pglite
claude mcp add gbrain -- gbrain serve
```

或者：

```bash
gbrain init --pglite
codex mcp add gbrain -- gbrain serve
```

这一条很值得注意，因为它代表 `gbrain` 的“轻量切入点”不是做完整知识库平台，而是先成为编码代理的长期记忆插件。

### 3. 独立 `CLI` 使用

文档里也提供了纯命令行方式：

```bash
bun install -g github:garrytan/gbrain
gbrain init --pglite
gbrain doctor
gbrain import ~/notes/
gbrain query "what themes show up across my notes?"
```

从这里可以看出，它既能作为代理后端，也能作为单独的本地工具存在。

## 这个项目最值得关注的几个点

### 1. 它的产品形态很清晰

很多开源知识库项目功能很多，但主线模糊。

`gbrain` 的主线很明确：

- 给人和代理提供长期记忆
- 给查询提供综合回答，而不只是检索
- 给知识内容自动补关系图谱
- 给团队提供“公司大脑”形态

### 2. 它不是传统意义上的“第二大脑”应用

如果你期待的是：

- 优雅的笔记编辑器
- 可视化的知识卡片界面
- 面向普通用户的低门槛交互

那 `gbrain` 可能不是这个方向。

它更偏：

- 基础设施
- 代理工作流后端
- 知识操作系统
- 面向重度用户和开发者的能力层

### 3. 它明显偏“工程化”

从 `package.json` 和 `README` 能看出，这个仓库很重视：

- `CLI`
- 测试与校验脚本
- `MCP` 对接
- 多引擎支持
- 任务队列
- 评测体系

所以它不是一个“小而美”的工具，而是一个野心比较大的系统级项目。

### 4. `README` 的营销感很强，但能力也确实成体系

这个仓库的文案风格很强势，带有明显的创始人式表达。

这有两个解读：

- 一方面会让你感觉“宣传味比较重”
- 另一方面也说明作者对产品定位非常明确，不是随便拼的功能集合

对做项目研究的人来说，这种项目反而值得看，因为它通常代表了比较完整的产品思考。

## 适合谁

我认为 `gbrain` 比较适合下面几类人：

- 已经在用 `Claude Code` / `Codex` / `Cursor`，想给代理增加长期记忆的人
- 有大量 `Markdown`、会议、邮件、项目资料，想统一成可查询知识脑的人
- 想做“公司知识中台”或“团队记忆层”的创业者
- 对 `MCP`、`Agent`、知识图谱、`RAG` 基础设施感兴趣的开发者

## 不太适合谁

如果你的需求只是：

- 简单记笔记
- 本地全文搜索
- 做一个轻量个人知识库
- 希望零配置、零概念负担地直接上手

那 `gbrain` 可能会偏重。

它的价值更像是“可扩展的脑基础设施”，而不是“开箱即用的轻笔记工具”。

## 我的整理结论

`gbrain` 可以理解成一个面向 `AI Agent` 时代的知识基础设施项目。

它的独特点不在于单个功能，而在于把下面几件事合在了一起：

- `Markdown` 知识仓库
- `Postgres` / `PGLite` 检索引擎
- 混合搜索
- 自动知识图谱
- 综合回答
- `MCP` 接入
- 代理自动安装与持续运维

如果你关心的是“如何让代理真正拥有长期记忆和上下文积累能力”，那 `gbrain` 是一个非常值得深挖的项目。

如果你关心的只是“找个知识库工具记笔记”，那它可能有点过于庞大。
